# Deck

What a lecturer brings to a subject: [slides](SLIDE.md) in the order they'd be given if nobody interrupted, plus every slide that was ever made up along the way. A deck says what it's about and who it's for. It might be prepared carefully ahead of time, or start empty and be built as the [lecture](LECTURE.md) goes. These are the same kind of thing. A prepared deck is just one that already has a main line.

## Invariants

- A deck has one main line: the slides in the order they'd be given uninterrupted. Slides off the main line stay attached to the point where they came up.
- **Giving a deck doesn't use it up.** The same deck can be given any number of times, to different listeners, by different lecturers.
- **A deck stands on its own.** Everything a lecturer needs to give it is in the deck. A lecturer who can't reach the code, the paper or the person the deck was made from can still give it.
- A deck belongs to no lecturer and no runtime. Any lecturer can give any deck.
- The main line changes only on purpose. A slide made up during a lecture is kept with the deck, but it joins the main line only when someone puts it there.
- A deck can be improved between lectures. The [questions](QUESTION.md) it keeps getting show where.
